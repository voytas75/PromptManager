# Draft prompt CLI v1 — bounded delivery ledger

Status: implementation verified locally in WSL after independent review; delivery SHA/CI are reported separately from this local acceptance record. Native Windows acceptance has not been run. Product authority: `docs/product-ssot.md`.

## Scope / contract

- Add `draft` family: recent list, add, show, literal find, confirmed permanent delete. Promotion and editing are separate future decisions. Drafts are `prompts` with `ext2.capture_state = "draft"`; standalone notes remain independent in `prompt_notes`.
- Add accepts one nonblank text source (positional, `--body`, UTF-8 `--file`, `--from-stdin`), optional title/source, returns a fresh UUID and records CLI origin. Title derivation is deterministic; avoid importing PySide6. No paid/provider request or background embedding/index write for capture. Newly captured drafts have no `ext4` vector.
- List/find are bounded (default 20, 1–100), newest-modified-first, literal SQLite search over title, description and body; show returns full body, without vector data. Full canonical UUID for show/delete. JSON success on stdout or sanitized error on stderr.
- Delete requires `--yes` outside TTY or with JSON; TTY confirmation defaults No. **Fail closed** if Redis caching is configured (no cache invalidation/coordination seam is provided in this first slice). Verify current draft state under a SQLite write lock before deletion; inspect existing Chroma metadata read-only, and only open the writable Chroma client when a matching vector ID is present. Then remove the prompt/dependent rows via FK cascade and record CLI activity. Index preflight failure retains SQLite; an uncertain vector cleanup or SQLite failure after vector removal returns `PARTIAL_DELETE` and requires inspection of both stores. No new catalog or index on read/mutation.
- Both `python -m main` and installed `prompt-manager` dispatch early without GUI/full-manager bootstrap. Use a temporary isolated catalog for all mutating verification; do not write to the selected user catalog. Do not change GUI, schema, provider settings, or security policy.
