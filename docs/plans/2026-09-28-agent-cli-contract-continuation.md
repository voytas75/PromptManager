Status: zamknięty — A–D dostarczone i zweryfikowane; E jest osobną, odłożoną decyzją poza kryteriami zamknięcia tego planu. Cały CLI nie jest przez to „agent-ready”. ## Decyzja i kolejność

Naprawiać po jednej granicy kontraktu; zachować `prompt-add --json PAYLOAD` jako **wejście**, `--result-json` jako **wynik**. Bez zmian zależności, GUI, HTTP, providerów live, szerokiego globalnego handlera błędów i migracji danych. Użytkownik autoryzuje lokalną implementację i plan, nie automatyczny push; commit tylko po osobnej decyzji/zgodnie z zakresem. Alternatywa: osobne API/adapter; wrócić do niej przy potwierdzonej potrzebie sesji współbieżnych lub zdalnych.

### D — semantyka filtrów `prompt-find` (zakończony lokalnie)

- Wybór: obecny limit kandydatów z jawnym statusem „przeszukano tylko N” albo filtrowanie przed limitem z inną strategią retrieval. Nie nazywać pustego wyniku globalnym brakiem dopasowania; ocenić koszt/semantykę rankingową przed zmianą. Tylko po ustaleniu kontraktu RED/GREEN i provider-free regresja.
- Decyzja: utrzymać istniejący top-k semantic retrieval, liczbę wywołań i domyślny JSON array/text. Dodać opt-in `prompt-find --json --explain` z kopertą `{results:[...],retrieval:{scope:"retrieved_candidates",requested_limit:N,retrieved_count:N,matched_count:N}}` na sukcesie, również gdy wyniki są puste. `scope` oznacza wyłącznie kandydatów otrzymanych z rankingu (nie cały katalog), a `--explain` bez `--json` jest błędem parsera. Puste `results` nie dowodzi braku rekordu poza top-k. To zgodne z historyczną decyzją o filtrach po rankingu i zachowuje dotychczasowy kształt bez flagi. Alternatywa: filtrowanie przed ograniczeniem/reranking; wymaga osobnego dowodu jakości, kosztu i wymagania kompletności. RED/GREEN bez live provider call.
- Wynik: 3 RED dla parsera/explain, potem GREEN; provider-free test z kandydatem poza limitem potwierdził jedną operację retrieval i `retrieved_count=1`, `matched_count=0`, zamiast pozornej globalnej nieobecności. Dodatkowe testy sprawdzają niepuste wyniki i oba realne entrypointy z izolowanym katalogiem/konfiguracją. Domyślna tablica JSON i tekst bez zmian, help/README/changelog uzupełnione. Testy sąsiednie: 195 passed; pełna bramka po D **1225 passed, 1 skipped, 83.18%**. Ruff check/format, skonfigurowany + scoped Pyright, `uv lock --check`, `git diff --check` — pass. Bez live provider call, commita lub pusha. `retrieved_count` liczy rekordy po weryfikacji przez `search_prompts`, a nie surowe trafienia Chroma; nie obiecuje kompletności katalogu.
